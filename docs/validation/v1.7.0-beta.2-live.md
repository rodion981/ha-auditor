# v1.7.0-beta.2 live regression validation

Date: 2026-10-14 (local time). Runtime: Home Assistant Core 2026.9.3.
Release code: `319e57e6923c471b351b29c4391a2edb9f8876c2`.

## Scope and method

The exact beta.2 release was downloaded through HACS, followed by a Home
Assistant Core restart. The integration page reported `1.7.0-beta.2` and seven
entities. Five HACS integrations were present, with no actual pending updates.
No GitHub token was configured.

Upgrade-path scenarios used temporary Developer Tools state overrides on
existing update entities. These were controlled fixtures, not real installed
versions, downgrades or pending updates. Release evidence came from actual
public GitHub release notes. Notification delivery and network settings were
not changed.

## Regression results

1. **Optional fields can be cleared.** A temporary notification action and
   exclusion list were saved, displayed when reopening the form, then cleared
   to empty strings. Reopening confirmed both fields remained empty. No audit
   notification was sent while the temporary action was configured.
2. **Generic risk descriptions no longer become update risks.** The HA Auditor
   `v1.3.0 -> v1.6.1` fixture produced a complete eight-step release path with
   classification rules version 6, feature severity, zero breaking-change and
   security-fix signals, and one feature signal. No update-risk finding opened.
3. **Explicit risk evidence remains effective.** HACS `1.34.0 -> 2.0.5`
   produced a complete six-step path and a critical finding. The actual 2.0.0
   notes supplied a breaking change and an explicit minimum Home Assistant
   version of `2024.4.1`. Aggregate counts were one breaking change, one
   deprecation and one feature.
4. **Incomplete evidence cannot resolve or downgrade the known risk.**
   With installed version `qa-unmatched-installed` and the same HACS target,
   two successful audits checked 2/2 selected repositories with no errors.
   The path was partial and its current assessment minor; the existing
   critical HACS finding remained active with `clear_confirmations: 0`,
   attention on and one to-do item after both audits. Successful attempts:
   `2026-10-13T22:19:38.008242+00:00` and
   `2026-10-13T22:20:21.385777+00:00`.

Intermittent GitHub DNS timeouts also occurred. Those audits correctly reported
partial coverage rather than a clean result and preserved the active risk.
Retries recovered without modifying network configuration.

## Cleanup and final state

Both update entities' original states and attributes were restored. The
synthetic HACS finding was removed through the normal exclusion lifecycle,
then all exclusions were cleared. No storage files were edited. Original
settings were restored: no notification action or token, daily hour 9,
Sunday digest and unauthenticated request budget 45.

Two subsequent full ordinary audits succeeded at
`2026-10-13T22:25:09.050892+00:00` and
`2026-10-13T22:25:25.370062+00:00`. Each checked 5/5 repositories with idle
status, complete coverage, zero exclusions, zero errors and zero new releases.
Active and resolved findings were empty; attention and audit-problem sensors
were off, and the to-do count was zero. The final reported GitHub quota was 24.

## Evidence limits

The three reproduced beta.1 regressions passed targeted live revalidation.
This remains a prerelease: a real pending-update inventory, a live tag-only
path and request-budget behavior on a large inventory still need validation.
The controlled path tests do not substitute for those gates. Resolution after
two clean checks is covered by automated runtime tests, not claimed as a new
live test here; fixture removal used exclusions. This report does not claim a
Home Assistant Quality Scale tier or production certification.
